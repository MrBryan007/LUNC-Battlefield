# AI plan 2026-10-30

The 10/29 run shipped v12.0.39 to v12.0.42 (all four cycles deployed); its cycle-4 deploy phase never got an hours
record because the run ended before it logged. Today starts from main d7e83b0 (v12.0.42).

## Cycle 1 → v12.0.43 "Army line of sight" (v12.1 War Systems: "Still open: LOS for the market-army tanks")
The market armies (infantry, MBTs, SPGs) shoot at a random point near the price front, through hills, walls and bunkers.
New module `js/theaters/army-los.js`, hooked into the engine's `maybeFire` (fire visuals only):
1. Direct fire (infantry, MBTs) picks a real target: sample a handful of enemy ground units within reach (24 m) and
   engage the nearest one the shooter can actually see (`LB.los.trace`, tank sight 2.4 m, rifle 1.6 m, target centre
   0.9 m). Shots land on the target with a small spread (MBT 0.8 m, rifle 1.6 m).
2. If enemies are in reach but none is visible, the unit holds fire and re-checks in about 0.6 s (counted as "held").
   With nobody in reach the old suppressive fire at the front stays, so the line never goes quiet.
3. Indirect fire (SPGs) needs an observer: if a friendly infantry or MBT near the front can see the aim point, the
   round is observed (normal spread); otherwise it is unobserved and lands with 2.2x the spread.
4. Stats in `armyLos.getState()` (engaged, held, fallback, observed, unobserved, blockers) and a row in
   Map → WAR SYSTEMS. Kill switch `?armylos=0` (also off with `?los=0`).
Fire visuals only: never touches market data, army counts, the price-driven front or data-truth labels.

Result (cycle 1): all gates passed; deploying as v12.0.43.

## Cycle 2 → v12.0.44 "Mission editor, part 1" (v12.3: "Mission editor", not started yet)
Orders are always random from a fixed pool. New module `js/ui/mission-editor.js` with a panel in the Cmd sheet:
1. Build a mission: a name and a chain of 1 to 5 objectives, each with a target and a time limit (20-180 s). Objective
   kinds: hit N infantry / armor / artillery, reach a xN combo, score N points, collect N power-ups (when power-ups are
   on). Presets to start from ("Tank hunter", "Artillery raid", "Combo master").
2. Play: the chain runs through the normal ORDERS card (commander `nextMission` asks the editor first). Each objective
   done moves to the next; one failure ends the run. Result toast with the total time, best time saved per mission.
3. Save up to 6 missions on the device, and share one with a link `?mission=<code>` (compact base64 JSON) or a copy
   code; a link mission is queued when the game starts. Bad codes are rejected safely.
4. Hot-seat turns keep their own random orders (the editor stays out while hot-seat is running).
Game layer only: never touches market data, armies, the front or data-truth labels. Kill switch `?editor=0`.

Result (cycle 2): all gates passed; deploying as v12.0.44.
