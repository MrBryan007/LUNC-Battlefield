## Cycle 2 → v12.0.49 "After-action replay, part 3: share links" (v12.3 replay, last open item)
1. "Share link" in the replay viewer and a "Link" button on each saved replay. It packs the replay into the URL
   fragment (`#rp=…`, never sent to the server): JSON → deflate (CompressionStream) → base64url, prefix `z1.`; plain
   base64url `j1.` where CompressionStream is missing.
2. Adaptive fit under a 16 000-character link: thin the sampled units per side (24 → 12 → 8 → 4 → 0), then every 2nd /
   3rd / 5th frame, then trim to the most recent stretch. Events, the front, its LIVE / SIMULATED label, squads, Hill 402
   and score are always kept. The status says what was kept ("2 min 10 s · 8 units a side · 11.4 KB link").
3. Phones use the system share sheet (Web Share API) when it exists; otherwise the link is copied to the clipboard, and
   if that's blocked a read-only box with the link selected is shown.
4. Opening a link: on load the fragment is decoded (input capped at 40 000 characters, decompressed output at 600 KB,
   aborting a bigger stream), run through the same sanitizer as imports, opened in the viewer as "(shared)", and the
   fragment is removed from the address bar. Save keeps it on the device. A broken link shows a status message and
   the game loads normally.
Kill switch stays `?replay=0` (links are ignored). Read-only: never touches market data, armies, the front or labels.
