## Cycle 2 → v12.0.46 "After-action replay, part 1" (v12.3 "A replay system", not started)
The roadmap asks for a command log + RNG seed played back deterministically. That can't be exact here: the battle is
driven by live market prices and ~every system uses Math.random, so a re-simulation would diverge at once. Part 1 is a
**recorded** replay instead (honestly labelled RECORDED, not re-simulated), which still gives the after-action review:
1. New module `js/ui/replay.js`, kill switch `?replay=0`. Recorder samples every 2 s for the last 10 minutes (ring
   buffer, 300 frames): market front X (labelled with its data-truth source at that moment: LIVE / SIMULATED), score,
   ORDERS text, live unit counts per side and type, up to 24 sampled market-army units per side, all squads, Hill 402
   holder. Events from hooks: every Commander strike (ability, x, z), orders complete / failed, custom mission end.
2. Viewer: full-screen AFTER-ACTION overlay. Top-down canvas of the front (units as side-coloured dots, squads as
   chevrons with names, strikes as expanding rings, the front as a line with its truth label), a front-position chart
   with event ticks under it, Play/Pause, 1x/4x/16x, a scrubber (drag on phones), step to previous / next event, and
   an event list. Tapping an event while the game runs flies the live camera to that spot.
3. Save up to 2 replays on the device (compact integer arrays), Delete, and Export as a .json download.
4. Entry: AFTER-ACTION REPLAY panel in the Cmd sheet (Watch last N min, saved list). Esc closes the viewer.
5. Perf: sampling is O(units / stride), drawing only while the viewer is open. LOW / phones sample 16 units per side.
Never touches market data, armies, the front or data-truth labels; it only reads them.
